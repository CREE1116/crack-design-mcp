# 크랙 시스템 프롬프트 재구성

2026-09-04~05, 환각 게이트를 통과한 세션에 축자 인용을 요구해 얻은 관찰로 재구성한
크랙 런타임의 프롬프트 배치. 기계가 읽는 정본은 `crack_design/spec/crack_spec.yaml`
이고, 이 문서는 사람이 읽는 근거 대장이다.

## 근거 등급

| 등급 | 의미 |
|---|---|
| `[USER-OBSERVED]` | 게이트를 통과한 세션에서 축자로 확인 |
| `[OBSERVED]` | 제3자 역공학(dcinside 뤼튼 마갤 #961451), 교차검증됨 |
| `[MODEL-SELF-REPORT]` | 모델이 설명한 것. 관찰과 어긋나면 관찰을 따른다 |
| `[UNVERIFIED]` | 추정값 |
| `[ABSENT]` | 덤프에는 있으나 관찰에서 존재하지 않음 |

**환각 게이트**: 존재하지 않는 블록(`<emotion_matrix>`, `[Affection Ledger]`)을
물어 "모름"이 나오고 실재 블록만 답한 세션의 응답만 채택했다. 자세한 절차는
[probe-kit.md](probe-kit.md).

## 전체 배치

```
┌─ system ─────────────────────────────────────────────┐
│ # {페르소나명} Information                            │
│ ---                                                  │
│ (메인 프롬프트 전문)                                   │
│ keyword output                                       │
│ [Previous History]          ← 헤더만. 본문 없음        │
│ [최근 사건 타임라인]          ← 요약메모리 (매 턴 재작성) │
│ [캐릭터 관계도]                                       │
│ [주어진 목표]                                         │
└──────────────────────────────────────────────────────┘
┌─ chat messages ──────────────────────────────────────┐
│ 대화 이력이 여기로 들어간다 (시스템에 인라인 아님)        │
└──────────────────────────────────────────────────────┘
┌─ 마지막 user message ────────────────────────────────┐
│ (이번 입력. 라벨 없음)                                 │
│                                                      │
│ ## Additional Information & Rules   ← 최하단 = 최강    │
│ <recalled_history>   … </recalled_history>           │
│ <system_note>        … </system_note>                │
│ <knowledge_base>     … </knowledge_base>             │
│ ---                                                  │
│ [Roleplay Response]                                  │
└──────────────────────────────────────────────────────┘
```

`## Additional Information & Rules` 하위 3블록의 순서가 이 재구성의 핵심 수정이다.
역공학 덤프는 `system_note → knowledge_base → recalled_history` 라고 적었으나
축자 인용은 **`recalled_history` 가 맨 앞**임을 보였다.

## 블록별 근거

| 블록 | 등급 | 근거 |
|---|---|---|
| `[Previous History]` → `[최근 사건 타임라인]` 인접 | `[USER-OBSERVED]` | "그 바로 다음 줄" 질문에 `[최근 사건 타임라인]` |
| `[Previous History]` 에 본문 없음 | `[USER-OBSERVED]` | 위와 동일 + "관계도 위에 이전 응답 본문 있느냐" → 없음 |
| `## Additional Information & Rules` 하위 순서 | `[USER-OBSERVED]` | 해당 구간 축자 인용 |
| `[Roleplay Response]` 가 `</knowledge_base>` 아래 | `[USER-OBSERVED]` | 위/아래 질문에 "아래" |
| `keyword output` | `[USER-OBSERVED]` | 존재 확인 |
| `[User Message]` 라벨 | `[ABSENT]` | 앞 3줄 요구에 "없음" = 문자열 자체가 없음 |
| `=` 구분선 | `[ABSENT]` | "없음" |
| `[Story State — Reference Only]` | `[ABSENT]` | "없음" + 축자 인용에 미등장 |
| `[System Message]` | `[ABSENT]` | "없음" |
| `[Story State Level Definition]` | `[ABSENT]` | "없음" |
| `Pedophilic conversation …` 거부 문구 | `[ABSENT]` | 미확인 (조립에서 제외) |
| `This session is completely private` | `[ABSENT]` | "없음" |
| `Do not think silently` | `[ABSENT]` | "없음" |

`[ABSENT]` 7개는 스펙에서 **삭제가 아니라 주석 처리**했다. 작품별 설정 차이일
가능성이 남아 있어, 덤프 형태를 재현하려면 주석만 풀면 된다.

## 메모리 블록 실물

### `[최근 사건 타임라인]` — 요약메모리

```
### 퇴원 및 복귀
[⌛259] 2027년 12월 10일｜10:30｜헌터 협회 부협회장실 크리가 S급 헌터로 공식 승급 후 협회로 정식 복귀함. …

### 저녁 식사
[⌛259] 2027년 12월 10일｜19:45｜크리의 집 크리가 준비한 김치찌개와 집밥을 서리화와 함께 먹음. …
```

- 형식: `### 장면 제목` + `[⌛턴] 날짜｜시각｜장소 사건요약`
- **네 항목의 턴번호가 전부 동일(`⌛259`)** → 사건이 일어난 턴이 아니라 요약이 쓰인 턴.
  즉 누적이 아니라 **갱신 때마다 통째로 재작성**된다.
- 갱신 주기: 매 턴. (타임라인 `⌛N` = 마지막 응답 번호, 둘 다 259)
- 정렬: 작중 시각 오름차순(10:30 → 19:55). 오래된 것이 위.
- 주입 개수: 4

### `<recalled_history>` — 장기기억

```
### 병원에서의 눈
2027년 11월 28일｜08:15｜헌터협회 지정병원 특실 크리가 의식을 회복하고 곁을 지키던 서리화와 재회함. …

### 향후 계획
2027년 11월 28일｜08:30 크리는 완전한 회복을 위해 당분간 병원에 머물 예정임. …
```

- 형식: 타임라인과 같되 **`[⌛턴]` 스탬프가 없다.** 두 블록은 이 하나로 갈린다.
- **과거 사건만이 아니라 앞으로의 계획도 같은 형식의 항목**으로 들어간다(`### 향후 계획`).
- 주입 개수: 3
- 기록 빈도: 희소. 관찰된 턴번호가 ⌛85 → ⌛107 → ⌛114(간격 22, 7)로, 주기가 아니라
  사건 기반. 선정 기준은 `[MODEL-SELF-REPORT]` → `memory.longterm_criteria`.
- 모델은 실린 3개 밖의 항목을 "볼 수 없음". 서버 저장량은 모델로 검증 불가.

### `[캐릭터 관계도]`

```
### 서리화 (A급 헌터 / 부협회장)
크리의 아내이자 직속상관. 크리의 무모한 행동에 분노하면서도 그를 깊이 신뢰함. …

### 리에발트 (군주)
EX급 재앙. 크리의 엑스칼리버에 의해 완전히 소멸함.
```

- 형식: `### 이름 (직함 또는 등급)` + 산문. 한 줄 요약이 아니다.
- **퇴장·사망한 인물도 결말과 함께 남는다.**
- 주입 분량: 5줄

### `[주어진 목표]`

```
완벽하게 회복하여 일상으로 복귀하고 서리화와 함께 평온한 시간을 보내는 것.
```

전투 직후 입원한 국면에서 관찰됨. 유저가 타이핑한 문장이 아니라 현재 상황에서
유도된 값 → 장기메모리 기능으로 보아 기본 `goal_source: auto`. 유저가 설정하면 잠긴다.

### `<system_note>` — 유저노트

자유 서술. 관찰된 예시는 플레이어 캐릭터의 설정·능력 명세였다.

### `<knowledge_base>` — 발동된 키워드북

- 주입 개수: **3** (두 작품에서 확인)
- 우선순위: 매칭이 먼저 거르고, 그 안에서 **문서 순서**.
  편의점 세션에서 실린 3개의 문서 위치가 3 → 4 → 6 이었고 앞쪽 0·1·2 는 실리지 않았다.
  "상위 3개 무조건"이 아니다.
- 항목 최상위 헤딩은 `#`. 작품에 따라 설정이 아니라 규칙(`# 필수추론목록`,
  `# 문체 규칙`)이 들어가기도 한다.

## 저장 vs 주입

사용자 관찰: 요약메모리·관계도·장기기억 모두 **저장 칸 수 제한이 없다.**
한편 주입 개수는 두 세션에서 **4 / 3 / 5** 로 동일하게 재현되었다.

두 사실은 모순이 아니다 — 무제한으로 쌓아두고 정해진 수만 싣는다. 스펙은
`*_store`(저장, 기본 무제한)와 `*_slots`(주입, 유한)로 나눠 이를 반영한다.

## 아직 `[UNVERIFIED]`

- 키워드 매칭 방식 (substring / word / regex)
- NFKC 정규화, 대소문자 무시, 공백 처리 여부
- 컨텍스트 윈도우 크기 (턴 수 / 토큰 수)
- 단축어 라우팅 (system 첨부인지 user 치환인지)
- `<knowledge_base>` 주입 문자수 예산
- `[ABSENT]` 7개가 크랙 전역인지 작품별 설정 차이인지

## 재현 방법

`docs/probe-kit.md` 의 0단계 게이트를 먼저 통과시킨 뒤, 1~4단계를 순서대로 던진다.
**같은 세션에서 이어서** 물어야 게이트 결과가 유효하다. 두 번째 작품에서 같은 답이
나오면 `[USER-OBSERVED]` 를 교차검증된 `[OBSERVED]` 로 승격한다.
